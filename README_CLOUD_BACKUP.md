# Облачное резервное копирование ILU — пилот «Сборка»

Рабочий путь — `Архив ILU/Сборка/`. Все участки и смены Сборки отправляют JSON в эту папку. Папка должна существовать, ILU не создаёт подкаталоги. Для остальных департаментов облачная отправка не подключена.

Рабочая очередь хранится отдельно от тестовой. Тестовая папка и прежняя очередь сохраняются, а записи из неё не отправляются в рабочий архив.


## Подключение участка

1. Откройте ILU в Яндекс Браузере, где выполнен вход под корпоративным аккаунтом.
2. Проверьте департамент, полное название участка и смену в настройках матрицы.
3. Раскройте «Облачное резервное копирование · пилот «Сборка»» рядом с действиями резервирования.
4. Нажмите «Подключить Яндекс Диск». На официальной странице проверьте аккаунт и разрешения.
5. Одноразовый код введите в ILU и нажмите «Подтвердить код». Не отправляйте код, пароль или токен другим людям.
6. После успешного подключения очередь продолжит работу автоматически. При необходимости нажмите «Повторить отправку».

Используются Authorization Code с PKCE S256, публичный Client ID и Redirect URI `https://oauth.yandex.ru/verification_code`. Client Secret не используется. Для испытанного приложения предоставлены `cloud_api:disk.read`, `cloud_api:disk.write`, `cloud_api:disk.info` и права пользователя на Общий диск. Индивидуальные корпоративные ограничения могут потребовать участия ИТ.

Access token сохраняется в отдельной записи LocalStorage `ilu-yandex-auth-v1`: только `access_token`, абсолютное время `expires_at` и название/логин подключённого аккаунта, полученные от API. При F5 и повторном запуске того же профиля браузера ILU восстанавливает запись и проверяет токен запросом к API, не открывая OAuth. До успешной проверки новые отправки не начинаются. Статус проверки — «Восстанавливаем подключение...», успешного восстановления — «Яндекс Диск подключён».

При истечении срока или ответе HTTP 401 сохранённый токен удаляется и требуется новое подключение. HTTP 403 означает отсутствие прав: токен автоматически не удаляется. Сетевая ошибка также не удаляет авторизацию; после восстановления сети или нажатия «Повторить отправку» проверка повторяется. «Отключить аккаунт» удаляет запись из LocalStorage, очищает память и останавливает новые запросы, сохраняя очередь. Другие открытые вкладки того же хранилища получают уведомление об отключении. Отозвать разрешение на стороне Яндекса можно отдельно в управлении доступами Яндекс ID.

Это **сохранение и восстановление**, а не автоматическое продление. Refresh-токен не сохраняется и не используется; Client Secret, пароль, authorization code и PKCE verifier в LocalStorage не записываются. После успешного обмена verifier очищается. Авторизация не входит в JSON матрицы, локальный экспорт и облачную очередь IndexedDB. Если браузер запрещает запись LocalStorage, подключение доступно только на время вкладки и интерфейс предупреждает об этом.

LocalStorage доступен JavaScript приложения и не является защищённым хранилищем секретов. Используйте индивидуальные учётные записи Windows, блокируйте компьютер при уходе и не оставляйте разблокированный компьютер без присмотра. Не переносите профиль или запись авторизации на другой компьютер. Доступ к профилю, вредоносный код приложения или расширение с соответствующими правами могут привести к извлечению токена. Самодельное шифрование с доступным этому же JavaScript ключом не используется. Другой браузерный профиль требует отдельного подключения. Очистка данных браузера, приватный режим или изменение расположения/источника локального приложения могут потребовать повторного входа.

### Фактические параметры ответа OAuth

Реальное число `expires_in` и наличие `refresh_token` в ранее выполненных авторизациях не были зафиксированы; из HTTP 200 эти значения установить нельзя. При следующем обычном подключении блок показывает только безопасные метаданные: `expires_in` в секундах и наличие непустого поля `refresh_token`. Значения токенов, полный ответ OAuth и секреты не выводятся. Эти метаданные не сохраняются; после F5 остаётся только абсолютное время окончания в записи авторизации.

Тестовые `expires_in=3600` и короткий срок для проверки истечения — подмена API, а не измеренный срок реальной авторизации. Поддержка обновления без Client Secret не предполагается; разрешения OAuth-приложения не изменялись. Перезапуск Windows в автоматических проверках не выполнялся. Сохранение проверено после полноценного закрытия и повторного запуска браузерного процесса с одним постоянным тестовым профилем; оно зависит от сохранности профиля на диске.

23.11.2026 пользователь подтвердил результат проверки реального подключения в Яндекс Браузере после F5 и закрытия/повторного открытия: «работает всё, подключение остаётся». Значение `expires_in` и наличие `refresh_token` в этом живом ответе не сообщались; из факта сохранения подключения они не выводятся.

## Когда создаются копии

- Локальное сохранение матрицы и планов продолжает работать независимо от облака.
- Изменение матрицы или планов ставит снимок в отдельную очередь. Отправка начинается через 45 секунд после последнего изменения содержимого. Неотправленные промежуточные состояния объединяются.
- При ручном экспорте JSON локальному механизму и облачной очереди передаётся одна сериализация снимка, сформированного через `createApplicationBackup()`.
- Внутреннее автосохранение в LocalStorage не запускает скачивание JSON и не обходит разрешения на запись в локальную папку.
- Проверка неизменности не учитывает `exportedAt`, но это поле сохраняется в отправляемом JSON. Повторный экспорт неизменённой уже архивированной матрицы не создаёт облачный файл только ради нового времени экспорта.
- Уже отправляемый снимок сохраняется отдельно от нового ожидающего. Подтверждённые облачные файлы не удаляются.

Основная часть имени сохраняет департамент, участок, смену и дату. В облаке добавляется UUID операции, например `Сборка_Участок сборки салона 4_СменаA_23.11.2026_<UUID>.json`. Запрос URL загрузки всегда использует `overwrite=false`. При коллизии существующий файл не перезаписывается: выбирается новое уникальное имя. Между вкладками одного профиля отправку блокирует Web Locks API. На разных компьютерах действуют независимые UUID и запрет перезаписи со стороны API.

Отсутствие дублей при повторном сохранении и запуске проверяется по очереди и последнему подтверждённому состоянию данного браузерного хранилища. Глобальная дедупликация одинаковых матриц, независимо подключённых на разных компьютерах, не реализована. Отпечаток не включает время экспорта; возврат к более раннему содержимому после другой успешно архивированной версии считается новым состоянием.

## Очередь, ошибки и проверка результата

Над матрицей, сразу под шапкой, показывается крупный индикатор состояния. Без авторизации и после ручного отключения он сообщает «ЯНДЕКС ДИСК НЕ ПОДКЛЮЧЁН», при истечении токена или HTTP 401 — «ТРЕБУЕТСЯ ПОВТОРНАЯ АВТОРИЗАЦИЯ», при подтверждённой сетевой ошибке или недоступности API — «ОБЛАЧНОЕ СОЕДИНЕНИЕ ПОТЕРЯНО», при HTTP 403 — «НЕТ ДОСТУПА К ОБЛАЧНОМУ ХРАНИЛИЩУ». Баннер не зависит от количества ожидающих копий: при пустой очереди скрывается только дополнительный счётчик. Количество читается из IndexedDB. Успешный ответ API снимает предупреждение, а наличие токена само по себе не подтверждает соединение. При печати и в других разделах баннер скрыт. Для отключённых департаментов пилотный индикатор не показывается. Новых сетевых проверок ради баннера нет; локальное сохранение не блокируется.

Очередь, JSON-снимки и подтверждения хранятся в отдельной IndexedDB `ilu-cloud-backup-assembly-v1`. Производственный формат JSON и его LocalStorage-ключи не изменяются. Токены в IndexedDB не записываются. Очередь содержит производственные данные: обращайтесь с профилем браузера как с локальной базой ILU.

При потере сети, HTTP 429 и временных серверных ошибках повторы выполняются с увеличением интервала, обычно до 5 минут; числовой `Retry-After` сервера может увеличить ожидание. Ошибки доступа, некорректного пути и несовпадения содержимого требуют проверки и ручного повтора. Неудачная операция остаётся в очереди. После закрытия приложения очередь возобновляется при автоматическом восстановлении действительного токена; после истечения или отзыва токена — при новом подключении аккаунта. Закрытый браузер отправку не выполняет. Очистка данных браузера, приватный режим и потеря профиля не обеспечивают сохранность очереди.

«Успешно архивировано» показывается только после обратного скачивания файла и побайтового сравнения с сохранённым снимком. Если ответ на загрузку потерян, повтор сначала проверяет существующий файл. Результат не объявляется успешным только по выдаче URL загрузки.

При облачной ошибке продолжайте использовать выбранную локальную папку или скачивание JSON. Не удаляйте исправные локальные копии. Не копируйте токены через исходники, файлы, консоль или сообщения.

## Изолированное приёмочное испытание

Вне рабочего проекта подготовлена страница `integration-test.html` в каталоге эксперимента `ilu-oauth-experiment-20261123`. Она загружает рабочие `backup-module.js` и `cloud-backup.js`, подменяя доступ к основному LocalStorage адаптером в памяти. Пользователь выбирает копию JSON с планами, подключает Яндекс и сохраняет локальный JSON. Модуль отправляет те же байты в тестовую подпапку и выполняет обратную проверку. Проверять ошибку сети следует средствами DevTools, не изменяя корпоративные настройки безопасности.

Пользователь подтвердил реальный результат: «Успешно архивировано · побайтовая проверка пройдена», 23.11.2026, 19:53:32, в Яндекс Браузере. Отдельный полный прогон с подменённым API использовал историческую копию SE4 с планами ротации и подтвердил совпадение 662158 байт. Реальный тест не заменяет проверки отказов в изолированном окружении.

## Автоматизированные проверки разработчика

Используется существующая инфраструктура разработки; установки на заводские компьютеры не требуются.

```powershell
$env:CHROMIUM_PATH = 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
$env:ILU_CLOUD_FIXTURE = 'путь к доступной только для чтения копии ILU с планами.json'
node --test tests/cloud-backup.test.js tests/backup.test.js
```

Внешний API в этих тестах полностью подменён. Они не выполняют реальную авторизацию и не отправляют производственные данные в сеть. Проверяются PKCE, debounce, байты локального экспорта, очередь после перезагрузки, повторная авторизация, естественное истечение и отзыв токена, сетевой сбой, потеря ответа загрузки, коллизия имени, ошибка побайтовой проверки и параллельные вкладки.
