# ILU Project — руководство разработчика

ILU Project — браузерное приложение на HTML, CSS и JavaScript. Для работы интерфейса достаточно браузера. Node.js и Playwright используются для проверок. Пользовательские сценарии описаны в [инструкции по ILU Project](README_ILU_Project.md).

## Запуск и структура папки

Откройте [matrix.html](matrix.html) в Microsoft Edge. Альтернативный способ для разработки — локальный HTTP-сервер. При установленном Python выполните из корня проекта:

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8000/matrix.html`. Адрес с другим портом или именем хоста использует отдельное хранилище. Для испытаний используйте отдельный браузерный профиль.

В корне находятся HTML, CSS, изображения, JS-модули, README и npm-метаданные тестов. В [tests](tests) находятся тесты, фабрика данных и вспомогательные функции. Папка `Тестовые json` содержит пример резервной копии. Браузер самостоятельно этот файл не загружает. Установленные пакеты тестов находятся в `node_modules`.

## Загрузка и ответственность модулей

[Точки подключения в matrix.html](matrix.html) задают порядок классических скриптов. Код пользуется общей глобальной областью видимости. Таблица ниже следует порядку подключения.

| Файл | Назначение и зависимости |
| --- | --- |
| [storage.js](storage.js) | `loadState()` читает и проверяет основное состояние. `saveState()` сериализует данные из `app-state.js`. Функции вызываются после объявления состояния. |
| [app-state.js](app-state.js) | Массивы постов, операторов, их ID, уровней, явки и журналов. Состояние фильтров, справочник подразделений, создание ID и общие поля дат. |
| [stats-module.js](stats-module.js) | `calculateStatsSnapshot()` считает показатели матрицы, `recordStatsSnapshot()` обновляет историю, `renderStatsDashboard()` строит панель. Для аналитики ротации использует планы и журнал. |
| [placement-module.js](placement-module.js) | `logPlacement()`, `ensureDailyInitialPlacement()`, формы, фильтры и вывод журнала расстановки. Использует состояние матрицы, события факта и `saveState()`. |
| [training-module.js](training-module.js) | Формы, фильтры и журнал обучения, `applyTrainingValidation()`, комментарии и А1/М3. Изменения записей могут обновить квалификацию и расстановку. |
| [plans-module.js](plans-module.js) | `generateDevelopmentPlan()`, `generateRotationPlan()` и операции с календарными ячейками. Читает матрицу и журнал, пишет результат генерации в календарь и метаданные. |
| [matrix-rules.js](matrix-rules.js) | Активные статусы, эффективный уровень при постановке, совместимость операторов на посту, снятие несовместимой квалифицированной расстановки. |
| [ui-module.js](ui-module.js) | Вкладки, контекстные меню, элементы выбора, фильтры подразделения, дата и видимость инфокарт. |
| [matrix-render.js](matrix-render.js) | `renderMatrix()` строит таблицу, подсказки, итоги и индивидуальные показатели. Также запускает снимок статистики и сохранение состояния. Отображает изменения процессов. |
| [matrix-actions.js](matrix-actions.js) | Изменение уровня, расстановки, явки и ролей, операции с постами и операторами. Связывает постановку с журналом, обучением и подтверждением ознакомления с изменениями процесса. |
| [app.js](app.js) | Восстанавливает состояние, запускает первичную отрисовку, обновляет статистические карточки и формирует печать. |
| [plans-storage.js](plans-storage.js) | Загружает планы и настройки, оборачивает генераторы, снимает и восстанавливает месячные снимки. Управляет утверждением ротации, отображением факта, комментариями и помощником расстановки. |
| [excel-export.js](excel-export.js) | `exportCurrentTableToExcel()` оформляет копию экранной таблицы и скачивает Excel-совместимый HTML через Blob. |
| [backup-module.js](backup-module.js) | Проверка и упаковка состояния и планов, импорт JSON, резервирование в выбранную папку, напоминание о копии. |

При запуске `app.js` вызывает `loadState()`. Если сохранённого ключа нет, стартовые массивы очищаются для пустой матрицы. Затем проверяется первичная расстановка, восстанавливаются элементы интерфейса и отрисовываются матрица и журналы. `plans-storage.js` позднее загружает планы и восстанавливает календарные таблицы. Отдельные операции отрисовки сохраняют состояние, в том числе снимок статистики и миграцию комментариев обучения.

## Хранение и резервирование

| Где | Что хранится |
| --- | --- |
| LocalStorage, `ilu-se4-state-v1` | Матрица, квалификации и расстановка, явка, ID, обучение и валидации, журнал и события факта, изменения процессов, утверждения и комментарии ротации, статистические снимки и настройки подразделения. |
| LocalStorage, `ilu-se4-plans-v1` | Текущие снимки развития и ротации, история по ключам `YYYY-MM`, настройки генерации. |
| Другие локальные ключи и IndexedDB | Настройки интерфейса и напоминаний. Разрешённый дескриптор папки резервирования хранится в IndexedDB. |
| Резервный JSON | Формат `ilu-se4-backup`, версия `1`, метаданные и поля `state` и `plans`. |

`data[row][column]` содержит квалификацию, `attendanceData[row][column]` — постановку на пост. Строки и столбцы связаны с параллельными массивами постов и операторов, включая ID. А1/М3 привязаны к паре ID. Часть истории, например записи обучения и строки снимков планов, использует имена и названия. Сохранение данных зависит от профиля, адреса страницы и доступности браузерного хранилища. Для переноса между профилями применяется резервный JSON.

`createApplicationBackup()` запрашивает сохранение текущего состояния и планов и формирует копию из LocalStorage. `importApplicationBackup()` разбирает и проверяет JSON, запрашивает подтверждение, запускает скачивание защитной копии, записывает и перечитывает оба ключа. При ошибке записи пытается восстановить прошлые значения. После успешной записи перезагружает страницу. Штатное сохранение в папку использует `showDirectoryPicker()` и зависит от разрешений браузера.

### Ошибки сохранения и целостности

- При ошибке чтения основного состояния `saveState()` блокирует перезапись. Импорт может остановиться на обязательной защитной копии, поскольку она вызывает `saveState()`.
- `savePlans()` перехватывает исключение записи, поэтому резервирование может продолжиться с предыдущей сохранённой версией планов.
- Проверка `trainingRecords` подтверждает тип массива. Некорректная запись вроде `null` может пройти импорт и вызвать ошибку при миграции комментариев.
- Подтверждение обучения сопоставляет записи с матрицей по имени и названию. Переименование может нарушить связь, одинаковые имена могут направить обновление в другую колонку. Риск для ротации описан в [README ротации](README_ROTATION.md#факт-и-статистика).

## Печать и экспорт

`printSections()` создаёт отдельную композицию для печати матрицы, клонирует инфокарты и делит операторские позиции группами по 20. Короткие группы дополняются пустыми позициями. Код скрывает оригинальные элементы и синхронно вызывает `window.print()` после подгонки. Другие печатные разделы используют собственные целевые элементы.

`fitMatrixPrintComposition()` измеряет раскладку при ширине 289 мм и сравнивает высоту с 202 мм. Эти размеры соответствуют A4 Landscape с полями 4 мм. При переполнении NORMAL включается COMPACT. Для нескольких компактных блоков соответствующие строки выравниваются по максимальной измеренной высоте. Размер инфокарт при смене плотности проверяется отдельно. Компактный профиль задаёт ячейкам шрифт 5,5 px и зелёному маркеру 6 × 6 px. В NORMAL зелёный маркер 12 × 12 px. Размер синего маркера от профиля не зависит.

Допустимое переполнение ведёт к многостраничной печати. Недействительная измеренная геометрия вызывает ошибку подготовки. Очистка печатного состояния вызывается по `afterprint` или при перехваченном исключении и восстанавливает исходные классы и стили. В клоне инфокарт отдельные ID потомков могут дублироваться до очистки. Физическое число страниц зависит от браузера и настроек диалога. Для диагностики доступны `window.lastMatrixPrintMetrics` и `window.__ILU_PRINT_DIAGNOSTICS__`.

Excel-экспорт клонирует `#iluTable`, переносит цветовую семантику матрицы, назначает Arial 9/10/11 pt по типу ячейки, размеры, переносы и Office-совместимые параметры. Результат имеет расширение `.xls` и HTML-содержимое. Преобразование маркеров сопоставляет и некоторые буквальные значения. Например, латинская `O` вне ячейки статуса может превратиться в кириллическую `О`. Визуальную проверку и сверку значений в Excel проводите отдельно от проверки печати браузера.

## Тесты и безопасная работа

Для запуска тестов установите Node.js 20 или новее и используйте зависимости из lock-файла. Если зависимости ещё отсутствуют, выполните `npm ci`. Команды для Edge и состав набора приведены в [документации тестов](tests/tests.md).

- Для сценариев импорта, переименования, генерации и восстановления используйте копию данных в отдельном профиле.
- После изменения стартового кода проверяйте пустой профиль и загрузку валидной копии. При изменении состояния проверяйте размеры массивов, ID и повторную загрузку.
- После изменения печати проверяйте измерения и физические страницы PDF. После изменения экспорта сравнивайте ячейки и объединения и проверяйте открытие в Excel.
- Перед подготовкой коммита в репозитории проверьте `git status` и состав изменений. Локальные зависимости, резервные копии и производственные выгрузки исключайте из коммита.

Алгоритмы и ручные операции описаны отдельно в [README развития](README_DEVELOPMENT.md) и [README ротации](README_ROTATION.md).
