# Планирование развития компетенций операторов

## Назначение

Планинг развития ILU-Project автоматически формирует **месячный календарь обучения операторов**. В отличие от ротации, которая поддерживает уже освоенные посты, развитие направлено на **расширение компетенций** и увеличение взаимозаменяемости на участке.

Генератор стремится последовательно повышать:

1. **Покрытие постов** — количество операторов, имеющих уровень **L/U** на каждом посту.
2. **Поливалентность операторов** — количество постов, на которых каждый оператор имеет **L/U**.

Планирование ведётся с учётом текущей расстановки, допустимости снятия оператора с поста, сложности операций, эргономики и доступной календарной ёмкости.

## Какие данные учитываются

- **Матрица ILU:** уровни компетенций по каждой паре «оператор — пост».
- **Роли:** `НУ`, `СО`, `ДС` исключены из кандидатов на развитие. Отдельной проверки статуса явки в автоматическом генераторе развития нет.
- **Фактическая расстановка:** отметки `○` используются для проверки, можно ли освободить оператора для обучения.
- **Сложность и эргономика постов:** используются при выборе первого поста для оператора, у которого пока нет ни одного L/U.
- **Нормативы обучения:** индивидуальная настройка `trainingDays` по постам.
- **Лимит одновременных обучений:** параметр `maxConcurrentTrainings` (по умолчанию 2).
- **Месяц планирования:** текущий или выбранный для просмотра месяц.

Отметка **`△`** намеренно **не считается занятостью** в алгоритме развития: для виртуальной проверки текущей расстановки используются только `○`.

## 1. Как считается исходный уровень участка

Для каждого поста генератор подсчитывает, **сколько операторов имеют на нём L или U**. Это показатель покрытия поста.

Для каждого оператора подсчитывает, **на скольких постах у него есть L или U**. Это показатель поливалентности.

Например:

| Объект | Исходный показатель | Что означает |
|---|---:|---|
| Пост № 1 | 1 | Пост знают на L/U только один оператор |
| Пост № 2 | 3 | Пост знают на L/U три оператора |
| Иванов | 1 | Иванов освоил один пост на L/U |
| Петров | 4 | Петров освоил четыре поста на L/U |

Во время генерации эти показатели **виртуально увеличиваются** после запланированного обучения. Реальные уровни ILU при этом не изменяются.

## 2. Какие уровни подходят для развития

Генератор выбирает кандидатов на обучение в таком порядке:

| Приоритет | Текущий уровень на целевом посту |
|---|---|
| **1** | `Lкр` |
| **2** | `I` |
| **3** | `Iкр` |
| **4** | Нет уровня: пусто, `null` или `0` |

Операторы с **L/U** на выбранном посту не рассматриваются как кандидаты на дополнительное освоение этого же поста.

При равных уровнях система предпочитает свободного оператора, затем оператора с меньшей поливалентностью; при необходимости применяется стабильный порядок матрицы.

## 3. Завершение уже начатого обучения

**Первый обязательный этап** — найти пары, у которых одновременно:

- уровень компетенции **`Lкр`**;
- на этом же посту стоит отметка **`○`**.

Такое сочетание интерпретируется как уже начатое обучение, которое необходимо завершить.

Генератор добавляет соответствующее назначение с этапом **«Завершение Lкр»**. Пост блокируется от выбора новых кандидатов в рамках текущей генерации, чтобы не начинать на нём параллельно новое развитие.

Один оператор может получить **не более одного автоматического назначения** за одну генерацию, включая продолжение обучения.

## 4. Проверка безопасного освобождения оператора

Прежде чем отправить оператора на обучение, система проверяет, можно ли временно снять его с текущего производственного поста.

Если оператор занят (`○`), генератор создаёт виртуальную копию расстановки и оценивает, останется ли его исходный пост обеспеченным.

- Если снятие допустимо без замещения, обучение можно планировать.
- Если снимаемый оператор является критичным для покрытия поста, генератор пытается найти **цепочку замещений**.
- Для замещения рассматриваются другие подходящие операторы; при необходимости они тоже виртуально освобождаются со своих постов.
- Если допустимую по правилам алгоритма цепочку освобождения построить не удалось, кандидат **не включается** в план на этот пост.

При выборе замещающего оператора приоритет уровней следующий: **Lкр → I → L → U**. Затем учитываются свобода оператора и его текущая поливалентность. **Особенность реализации:** цепочка замещений может использовать кандидатов с `Lкр` или `I`, то есть проверка не равнозначна строгому требованию сохранить на каждом посту действующего оператора с L/U. Это нужно учитывать при утверждении плана.

**Важно:** это расчётная проверка, а не реальная перестановка персонала. Генератор не меняет фактические `○` и уровни ILU.

## 5. Ограничение для первого освоенного поста

Если у оператора **вообще нет постов с уровнем L/U**, первое развитие допускается только на постах с определённым сочетанием сложности и эргономики:

| Сложность поста | Эргономика | Допустимо для первого L |
|---|---|---|
| `C` | `green` | Да |
| `C` | `yellow` | Да |
| `B` | `green` | Да |
| Остальные сочетания | Любая | Нет |

Ограничение действует именно пока виртуальная поливалентность оператора равна нулю. После назначения первого развития виртуальный показатель увеличивается, но повторное назначение этому оператору в той же генерации всё равно запрещено.

## 6. Основная логика: динамическая лестница развития

После обязательных продолжений обучения генератор запускает последовательную лестницу:

**Посты 2L → Операторы 2L → Посты 3L → Операторы 3L → Посты 4L → Операторы 4L → ...**

Здесь `2L`, `3L` и т. д. означают **целевое количество освоенных постов у оператора или количество квалифицированных операторов у поста**, а не отдельный уровень квалификации `L2` или `L3`.

### Этап А. Развитие постов до N

Генератор выбирает посты, у которых меньше **N операторов с L/U**.

Сначала рассматриваются посты с наименьшим покрытием. Для каждого поста подбирается допустимый кандидат по приоритету квалификации и возможности освобождения.

После успешного назначения виртуальное покрытие поста увеличивается на единицу. Подбор продолжается до целевого количества либо до исчерпания допустимых кандидатов.

### Этап Б. Развитие операторов до N

Затем генератор рассматривает операторов, у которых меньше **N освоенных постов с L/U**.

В первую очередь выбирается **группа с минимальной текущей поливалентностью**, причём только среди тех, кому ещё можно подобрать допустимый пост.

Внутри группы первыми рассматриваются операторы, имеющие **меньше возможных вариантов развития**: это позволяет раньше использовать ограниченные возможности.

При выборе поста учитываются:

1. Текущий уровень оператора на посту: `Lкр → I → Iкр → нет уровня`.
2. Возможность направить свободного оператора без замещений.
3. Насколько редко выбранный пост подходит другим операторам текущей группы.
4. Текущее виртуальное покрытие поста.

После этапа операторов алгоритм повышает целевое значение **N** и повторяет последовательность, пока есть допустимые возможности и не достигнуты условия остановки.

## 7. Как рассчитывается срок обучения

Продолжительность определяется **по текущему уровню оператора на выбранном посту**:

| Уровень на посту | Длительность |
|---|---|
| `Lкр` | **10 рабочих дней** |
| `I` | **10 рабочих дней** |
| `Iкр` | Норматив `trainingDays` для поста |
| Нет уровня | Норматив `trainingDays` для поста |

Если для `Iкр` или отсутствующего уровня норматив задан некорректно, автоматический генератор использует **1 рабочий день** как запасное значение.

При распределении по календарю назначения с уровнем **`Iкр`** размещаются раньше остальных.

## 8. Размещение обучения в календаре

Для каждого назначения генератор ищет нужное количество свободных **будних дней** внутри выбранного месяца.

Проверяются следующие ограничения:

- не превышен лимит **одновременно идущих обучений** (по умолчанию 2);
- оператор не проходит два обучения в один день;
- на одном посту в один день не размещаются два обучения;
- набрано полное количество дней, необходимое для назначения.

Дни обучения могут быть **не подряд**, если часть дат занята или приходится на выходные. Субботы и воскресенья пропускаются; отдельные праздничные дни не проверяются.

### Что происходит, если дней не хватает

Если для очередного назначения нельзя найти **полный срок обучения** в выбранном месяце, генератор:

1. Не размещает это назначение частично.
2. **Останавливает дальнейшее автоматическое наполнение месяца.**
3. Оставляет в календаре только ранее полностью принятые назначения.
4. Откатывает виртуальные результаты тех назначений, которые не были фактически размещены.
5. Сохраняет служебную причину остановки: оператор, пост, требуемое и доступное количество дней.

В интерфейсе может появиться сообщение: **«План развития сформирован до доступной календарной ёмкости»**.

**Отличие от ротации:** генератор развития останавливается на первом назначении, которое не удаётся полностью разместить; генератор ротации может пропустить невыполнимую потребность и продолжить работу с другими.

## 9. Пример работы генератора

Допустим, на участке:

- пост № 1 знают на L/U только **один** оператор;
- пост № 2 знают **три** оператора;
- Иванов знает **один** пост;
- Петров знает **четыре** поста;
- у Сидорова на посту № 1 уровень `Lкр`.

Генератор сначала проверит, нет ли обязательного продолжения обучения `Lкр + ○`. Затем на этапе **«Посты 2L»** пост № 1 получит высокий приоритет, поскольку его покрытие ниже целевого значения 2.

Если Сидоров подходит по ограничениям и его можно безопасно направить на обучение, система создаст назначение. Затем она перейдёт к развитию операторов с недостаточной поливалентностью.

Фактический результат зависит от текущих `○`, доступных замещений, сложности и эргономики постов, уровней кандидатов и календарной ёмкости.

## 10. Результат и ручная корректировка

Календарь показывает:

- **строки** — производственные посты;
- **столбцы** — дни месяца;
- **имена** — запланированные обучения;
- **столбец «Срок»** — длительности обучений по посту;
- **выходные** — отдельно выделенные дни.

Доступны ручные действия:

- **Добавить обучение** через пустую ячейку `+` и выбор оператора.
- **Удалить все обучения выбранного оператора** из календаря через меню заполненной ячейки.
- **Изменить срок обучения** через ячейку в столбце «Срок»; допустимы целые значения от 1 до 365 рабочих дней.

**Ограничение ручного режима:** список выбора и проверки при ручном добавлении не полностью повторяют автоматический алгоритм. В частности, ручной выбор не выполняет всю виртуальную проверку замещений и лестницы развития. Поэтому ручные изменения следует проверять отдельно.

## 11. Что генератор не делает

- Не повышает фактический уровень оператора до L/U после составления плана.
- Не изменяет текущую расстановку `○` и `△`.
- Не создаёт автоматически записи о фактически проведённом обучении.
- Не гарантирует, что все потребности развития поместятся в один месяц.
- Не учитывает праздники отдельно от выходных.
- Не использует отметку `△` как признак занятости при подборе.
- Не заменяет подтверждение освоенной компетенции ответственным руководителем.
- Не проверяет явку операторов при автоматическом подборе кандидатов.

## Кратко об алгоритме

**Матрица ILU → покрытие постов и поливалентность → завершение Lкр + ○ → проверка безопасного освобождения → лестница «посты N / операторы N» → расчёт длительности → размещение в календаре → план развития.**
